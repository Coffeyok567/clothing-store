# Магазин одежды — HTTP-сервер

## Описание проекта

Ядро сайта магазина одежды: REST API на Go с встраиваемой базой данных SQLite. Сервер обслуживает гостей, клиентов, менеджеров и администраторов.

- Маршрутизация: стандартный `net/http`.
- База данных: SQLite (`modernc.org/sqlite`, чистый Go, без CGO), чистый SQL через `database/sql`.
- Конфигурация: переменные окружения и файл `.env`.
- Логи: структурированный JSON (`log/slog`).
- Идентификаторы всех сущностей — UUID.
- Сохранены все 27 методов бизнес-API из технического задания; дополнительно добавлены 4 маршрута авторизации (`/auth/login`, `/auth/register`, `/auth/logout`, `/auth/me`).

### Структура

```
cmd/server         точка входа
internal/database  подключение и миграции
internal/handler   HTTP-обработчики и маршруты
migrations         SQL-схема, добавление ролей (002_roles.sql), администратор по умолчанию
bruno              коллекция запросов для Bruno
```

### Авторизация и роли

Добавлена авторизация по логину и паролю как дополнительная возможность к исходному ТЗ. Пароли хранятся только в виде хешей PBKDF2-HMAC-SHA256 с индивидуальной солью. После входа сервер выдаёт случайную сессионную cookie `HttpOnly`; в базе хранится только хеш токена сессии. Срок действия сессии — 7 дней.

- `POST /auth/login` — вход по `login` и `password`.
- `POST /auth/register` — самостоятельная регистрация клиента.
- `POST /auth/logout` — выход и отзыв текущей сессии.
- `GET /auth/me` — данные текущего пользователя и его роль.
- Администратор по умолчанию: логин `admin`, пароль `Admin123!` (измените через `ADMIN_PASSWORD` в `.env` до первого запуска).
- Менеджеров и дополнительных администраторов создаёт администратор в панели «Управление → Пользователи», назначая логин, пароль и роль.
- Гость может смотреть каталог; после входа права берутся из роли пользователя в базе. Подстановка чужого ID больше не авторизует запрос.

Дополнительные таблицы авторизации создаются миграцией `migrations/003_auth.sql`.

## Инструкция по запуску

Требуется Go 1.24 или выше.

```bash
cp .env.example .env
go mod tidy
go run ./cmd/server
```

Переменные окружения (`.env.example`):

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `PORT` | порт сервера | `8080` |
| `DATABASE_PATH` | путь к файлу SQLite | `shop.db` |
| `UPLOAD_DIR` | каталог для загруженных фотографий | `uploads` |
| `ADMIN_PASSWORD` | начальный пароль администратора (используется только при первом создании учётных данных) | `Admin123!` |

При запуске применяются миграции: схема, роли `admin`, `manager`, `client`, таблицы учётных данных и сессий. Для существующей базы данные товаров и пользователей сохраняются; для стандартного администратора добавляются начальные учётные данные, если их ещё нет.

## Проверка через Bruno

Коллекция запросов [Bruno](https://www.usebruno.com/) лежит в папке `bruno/`. В ней четыре папки, по одной на роль; в каждой собраны все методы, доступные этой роли, и проверки запретов.

1. Откройте коллекцию: **Open Collection** → папка `bruno`. Если она уже была открыта, сначала закройте её (**Close Collection**).
2. Запустите сервер: `go run ./cmd/server`.
3. Адрес задан в **Collection settings → Vars** (`baseUrl` = `http://127.0.0.1:8080`, `adminId`). Адрес `127.0.0.1` используется вместо `localhost`, чтобы избежать блокировки IPv6.

Каждая папка самодостаточна: её можно запускать отдельно, в любом порядке и повторно. Запросы «Подготовка: ...» в начале папки создают нужные данные (менеджера, клиента, товары, заказ) от имени других ролей. Запуск роли: правая кнопка по папке → **Run**; запуск всего: правая кнопка по коллекции → **Run** → **Run Collection**. Запросы «Запрет: ...» и «Ограничение: ...» должны отвечать 400, 401, 403, 404 или 409, тесты ждут именно эти коды.

| Папка | Методы роли |
|---|---|
| 1 Администратор | `/role` (4), `/product` (5), `/photo` (3), `/user` (5), `/order` (список, по id, смена статуса), `/order_item` (получить), запреты |
| 2 Менеджер | `GET /product`, `GET /product/{id}`, `GET /order`, `GET /order/{id}`, `PUT /order/{id}`, `GET /order_item/{order_id}`, запреты |
| 3 Клиент | каталог, `/cart` (4), `POST /order`, свои заказы, `/order_item` (2), запреты |
| 4 Гость | `GET /product` (фильтры, сортировка, страницы), `GET /product/{id}`, `GET /photo/{id}`, запреты |

Чтобы добавить новый товар в корзину: администратор создаёт товар (`POST /product`, в ответе `id`), затем клиент отправляет `POST /cart` с `{"product_id": "<id>", "count": 1}`. В Bruno это запросы «Подготовка: создать товар Новинка» и «Корзина: добавить новый товар «Новинка»» (папка 3).

## Сценарии использования

- **Гость** смотрит каталог (фильтры, сортировка по цене, страницы), карточку товара и фотографии.
- **Клиент** смотрит каталог, кладёт товары в корзину, меняет количество, оформляет заказ из корзины, смотрит историю своих заказов и их состав.
- **Менеджер** смотрит каталог и заказы клиентов (фильтры по статусу и датам), меняет статус заказа.
- **Администратор** управляет товарами, фотографиями, ролями и пользователями, смотрит заказы и меняет статус.

| Метод | Гость | client | manager | admin |
|---|:-:|:-:|:-:|:-:|
| `GET /product`, `GET /product/{id}`, `GET /photo/{id}` | + | + | + | + |
| `POST/PUT/DELETE /product`, `POST/DELETE /photo` | | | | + |
| `/role`, `/user` (все методы) | | | | + |
| `/cart`, `POST /order`, `POST /order_item` | | + | | |
| `GET /order`, `GET /order/{id}`, `GET /order_item/{order_id}` | | свои | все | все |
| `PUT /order/{id}` (смена статуса) | | | + | + |

Статусы заказа: `Принят`, `В работе`, `Собран`, `Готов к выдаче`, `Отменён`.

## Примеры curl-запросов

Сначала войдите и сохраните cookie сессии. Для разных ролей используйте отдельные cookie-файлы:

```bash
# Администратор (смените начальный пароль после первого входа)
curl -i -c admin.cookies -b admin.cookies -X POST localhost:8080/auth/login \
  -H "Content-Type: application/json" -d '{"login":"admin","password":"Admin123!"}'

# Посмотреть текущую учётную запись
curl localhost:8080/auth/me -b admin.cookies

# Выйти
curl -X POST localhost:8080/auth/logout -b admin.cookies
```

В защищённых запросах используйте `-b admin.cookies` (или cookie-файл другой роли), а не заголовок `X-User-ID`. Клиент может зарегистрироваться самостоятельно:

```bash
curl -i -c client.cookies -X POST localhost:8080/auth/register \
  -H "Content-Type: application/json" \
  -d '{"name":"Иван","email":"ivan@example.com","phone":"+79001234567","login":"ivan","password":"StrongPass123"}'
```

Для входа менеджера/клиента, созданного администратором, используйте `POST /auth/login` с его логином и паролем и отдельный cookie-файл. В браузере cookie сохраняется автоматически.

### Пользователи и роли (администратор)

```bash
curl localhost:8080/role -b admin.cookies
curl -X POST localhost:8080/role -b admin.cookies -d '{"name":"courier"}'
curl -X PUT localhost:8080/role/<id> -b admin.cookies -d '{"name":"supplier"}'
curl -X DELETE localhost:8080/role/<id> -b admin.cookies

# Администратор создаёт пользователя с логином, паролем и ролью
curl -X POST localhost:8080/user -b admin.cookies -H "Content-Type: application/json" \
  -d '{"name":"Иван","email":"ivan@example.com","phone":"+79001234567","login":"ivan","password":"StrongPass123","role":"<role_id>"}'
curl "localhost:8080/user?page=1&limit=20" -b admin.cookies
curl localhost:8080/user/role/<role_id> -b admin.cookies
curl -X PUT localhost:8080/user/<id> -b admin.cookies \
  -d '{"name":"Иван","email":"ivan@example.com","phone":"+79001234567","role":"<role_id>"}'
curl -X DELETE localhost:8080/user/<id> -b admin.cookies
```

### Товары

```bash
curl -X POST localhost:8080/product -b admin.cookies \
  -d '{"name":"Куртка","type":"куртка","gender":"м","size":"L","color":"чёрный","description":"Тёплая куртка","brand":"Nord","season":"зима","price":9990}'

# Фильтры: type, gender, size, color, brand, season; sort=price_asc|price_desc; page, limit
curl "localhost:8080/product?gender=м&season=зима&sort=price_asc&page=1&limit=10"
curl localhost:8080/product/<id>
curl -X PUT localhost:8080/product/<id> -b admin.cookies \
  -d '{"name":"Куртка","type":"куртка","gender":"м","size":"L","color":"синий","description":"Тёплая куртка","brand":"Nord","season":"зима","price":8990}'
curl -X DELETE localhost:8080/product/<id> -b admin.cookies
```

### Фотографии

```bash
curl -X POST localhost:8080/photo -b admin.cookies -F product_id=<product_id> -F file=@photo.jpg
curl localhost:8080/photo/<id> -o photo.jpg
curl -X DELETE localhost:8080/photo/<id> -b admin.cookies
```

### Корзина (клиент)

```bash
CLIENT=<id клиента из ответа POST /user>
curl -X POST localhost:8080/cart -b client.cookies -d '{"product_id":"<product_id>","count":2}'
curl localhost:8080/cart/$CLIENT -b client.cookies
curl -X PUT localhost:8080/cart/<id> -b client.cookies -d '{"count":3}'
curl -X DELETE localhost:8080/cart/<id> -b client.cookies
```

### Заказы и элементы заказа

```bash
# Клиент: заказ из текущей корзины
curl -X POST localhost:8080/order -b client.cookies

# Клиент видит свои заказы, менеджер и администратор — все
# Фильтры: status, from, to (RFC3339); page, limit
curl "localhost:8080/order?status=Принят&from=2026-01-01T00:00:00Z&to=2026-12-31T23:59:59Z&page=1" -b admin.cookies
curl localhost:8080/order/<id> -b client.cookies

# Менеджер или администратор: смена статуса
curl -X PUT localhost:8080/order/<id> -b admin.cookies -d '{"status":"В работе"}'

# Клиент: добавить позицию в свой заказ со статусом «Принят»
curl -X POST localhost:8080/order_item -b client.cookies -d '{"order_id":"<order_id>","product_id":"<product_id>","count":1}'
curl localhost:8080/order_item/<order_id> -b client.cookies
```

В ответах по заказам и корзине рядом с идентификаторами приходят имена: `user_name` у заказа, `product_name` у позиций заказа и корзины.

## Реализованный функционал

- Все 27 методов из технического задания: товары, фотографии, роли, пользователи, корзина, заказы, элементы заказа.
- Пагинация (`page`, `limit`) для списков товаров, пользователей и заказов.
- Фильтрация товаров по типу, полу, размеру, цвету, бренду и сезону; сортировка по цене.
- Фильтрация заказов по статусу и интервалу времени.
- Разграничение прав для гостей, клиентов, менеджеров и администраторов; клиент видит только свои корзину и заказы.
- Загрузка фотографий (jpg, jpeg, png, webp, до 5 МБ) с хранением файлов на диске.
- Заказ создаётся из корзины в одной транзакции, цена фиксируется на момент заказа.
- Пользователя с заказами удалить нельзя (ответ 409), чтобы не терять историю заказов.
- SQL-запрос добавления ролей в дереве проекта (`migrations/002_roles.sql`).
- Конфигурация через `.env`, структурированные JSON-логи, сообщения об ошибках на русском в поле `error`.
- Коллекция Bruno с проверками по каждой роли.

### Дополнения к ТЗ

- Поле `count` в элементе заказа (количество единиц товара).
- Авторизация по логину/паролю, сессионные cookie и проверка роли на сервере.
- Роли определяются по имени (`admin`, `manager`, `client`) — не переименовывайте их.

## Ограничения учебной версии

- Для промышленного развёртывания следует включить HTTPS, настроить резервное копирование БД и задать собственный сложный `ADMIN_PASSWORD` до первого запуска.
- Удаление файлов фотографий при удалении товара (записи удаляются каскадом, файлы остаются на диске).
- Автоматические тесты.
- Ограничение допустимых переходов между статусами заказа.

## Готовый веб-сайт

В корне проекта добавлена папка `web/` с интерфейсом магазина. После запуска сервера откройте:

`http://127.0.0.1:8080`

### Быстрый запуск в Windows
1. Установите Go версии 1.26 или новее (версия указана в `go.mod`).
2. Распакуйте весь архив в отдельную папку.
3. Запустите `ЗАПУСК_В_WINDOWS.bat` двойным щелчком либо откройте терминал в этой папке и выполните `go run ./cmd/server`.
4. При первом запуске Go скачает зависимости, создаст `shop.db`, применит SQL-миграции и создаст папку `uploads`.
5. Откройте сайт в браузере по адресу `http://127.0.0.1:8080`.

### Вход в интерфейс
Нажмите кнопку «Войти» в правой части шапки сайта.
- Клиент может создать аккаунт самостоятельно через «Зарегистрироваться».
- Менеджера и дополнительные учётные записи создаёт администратор в разделе «Управление → Пользователи».
- Начальный администратор: логин `admin`, пароль `Admin123!`. Для нового проекта задайте свой пароль через `ADMIN_PASSWORD` в `.env` до первого запуска.
- После входа сайт автоматически показывает разделы, соответствующие роли аккаунта. Кнопка профиля позволяет выйти из учётной записи.

### Важное замечание о составе исходников
В присланном текстовом дампе отсутствовали файлы каталога `migrations/`, хотя `internal/database/database.go` импортирует пакет `clothing-shop/migrations` и ожидает SQL-файлы. Чтобы проект собирался как самостоятельная папка, я добавил `migrations.go`, `001_schema.sql` и `002_roles.sql`. SQL-структура восстановлена по именам таблиц и полей, которые использует присланный Go-код; это восстановленные файлы, а не оригиналы из вашего дампа.
